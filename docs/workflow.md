# Website session workflow

Status: living — last reviewed 2026-09-22

## Start a session

Use the [shared session rules](../../werkflow-business/docs/workflow.md#establish-the-current-context) to establish repository freshness, clean or dirty state, and active writers. Apply them to the website before editing and to business sources before relying on them.

Open this repo for page implementation. Read the business offer, avatar, acquisition context, and copy standard as the task requires. Use the app's verified release evidence for availability claims.

If a sibling is busy, do not pull, switch, stash, or reset it. Read a completed committed version or report the missing evidence. Do not base current product claims on the app's dirty working tree.

## Review a change

For documentation and skills, follow the [shared review procedure](../../werkflow-business/docs/workflow.md#review-a-change). Check this repo's doc index, relative links and fragments, both skill mirrors, shared-skill parity with business, and the CLAUDE.md import of the local AGENTS.md.

For future page implementation, add the actual build and browser checks once the stack exists. Review each page's audience, offer revision, claims, German copy, reading level, accessible interaction, and mobile layout. Do not invent test commands or claim that a preview passed when no site exists.

Finish with a deletion pass. Remove unused files, duplicate facts, speculative scaffolding, and copy that does not help the reader act.

## Publish separately from the app

Commits and pushes require the user's request. Publication also requires authorization for the relevant hosting action. A separate Vercel project using Next.js is intended, with werk-flow.app and www.werk-flow.app. No Vercel project, DNS change, or deployment configuration is created by this foundation. GitHub publication alone does not implement or launch the site.

When hosting is introduced, document this website's own preview and production mapping here. The app's partner-preview branch, Supabase projects, and release procedure are not inherited automatically.

Record the business revision and product-release evidence used by a published page. After an offer or relevant product change, review affected live pages against those sources. This is an editorial responsibility until a real check is implemented.
